# Why Arkiv — Shankh

**If you swapped Arkiv for Postgres or any other database, what would your users lose?** The alarm itself. In the October 2026 LiteLLM attack, the attacker deleted GitHub Action workflow records to limit what investigators could see (project-overview.md §2.1, stage 3) — whoever controls the database controls the evidence. On Arkiv, a `shankh.report` belongs to the wallet of the machine that found the problem, not to Shankh, not to the package's maintainer, and not to anyone who compromises the publisher's infrastructure. Three things a database couldn't give us:

- **Alarms nobody can quietly edit.** Every alarm is created `readonly`: its contents can never change, not even by the reporter who wrote it. So someone who steals a reporter's key can't flip an alarm to "clean" or point it at a different build. Proven live: an edit attempt sent by the alarm's own owner was refused by the chain ("entity … was created readonly, so its contents can never change"). The honest limit, which the same error message states: the owner can still delete or transfer it — read-only is not undeletable.
- **Alarms the community keeps alive.** Every alarm is also created with `permissionlessExtension`: any machine that re-checks it and confirms the bad build can extend its lifetime, without being able to change what it says. Proven live: machine B, with its own wallet, extended machine A's alarm after confirming it. In the litepaper's words, reference material "immutable and extendable by anyone, so readers who value it keep it alive."
- **No server between machines.** This is the litepaper's "transport for a decentralized protocol" pattern: machines exchange signed records, and the protocol logic — whose alarms to trust, re-checking every alarm locally before acting — stays in each client. "There is no relay server to run or to trust, and every message carries its author's signature." Trust is anchored in the signer Arkiv records (`$creator`), matched against reporter names on ENS.

**What did you keep off Arkiv, and why?** The local inventory and exposure snapshot (what's installed, what credentials it could reach) never leaves the device — see plan-2.md "Privacy". Arkiv holds only evidence meant to be shared: the report itself, not the victim's exposure. Reads go by reporter, never by package, so even the query reveals nothing about what a machine runs.
