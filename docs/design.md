# Design — Shankh

How it actually works, kept precise about what is real and what is stubbed. Sections mirror the components in [`plan-2.md`](../plan-2.md)'s Design section, which is the detailed reference — this file tracks implementation state, not re-explain the design from scratch.

## Inventory (`shankh/shankh/inventory/`)
**Status: built, the RECORD-reading half.** `installed_package()` reads an installed package's actual on-disk files and their sha256 hashes straight from pip's `RECORD` — the ground truth `shankh.verify` diffs against. Discovering *other* Python interpreters/venvs and Docker images (the broader "what's on this machine" inventory plan-2.md describes) is still not started.

## Verification (`shankh/shankh/verify/`)
**Status: built and proven live**, for pure-Python packages. `shankh verify <pkg>==<version>` fetches the package's published sdist (real PyPI JSON API, or a local `--find-links` replay index for the demo) and diffs it file-by-file against what's actually installed. Untraceable files are flagged; `.pth`/`sitecustomize.py` paths specifically are CRITICAL — the real LiteLLM 1.107.0 persistence mechanism. Proven against a real clean PyPI package (`idna==3.20`, no false positives) and a real malicious wheel built for this test (correctly flagged CRITICAL). Scope note: this is a file-provenance diff, not a `--network none` compiled rebuild — for a pure-Python package the sdist already *is* the source, so no compile step is needed; a real sandboxed build is still the right next step for packages with a native build step that could itself be tampered with (not the LiteLLM case). `verify()` now also checks kill signal #2 (`shankh/shankh/ens/`, below) and forces the tier to CRITICAL if the maintainer has revoked this exact artifact on-chain, independent of what the rebuild diff found.

## ENS revocation check (`shankh/shankh/ens/`)
**Status: built and wired into `verify()`.** Shells out to `cast` to replay the real `resolve()` call shape (`scripts/ens/register-tree-sepolia.sh` step 10) and read `shankh.revoked` off a package's live resolver. Not configured unless `PACKAGE_RESOLVER_ADDRESS`/`PACKAGE_DNS_ENCODED_NAME`/`SEPOLIA_RPC_URL` are set, in which case it silently contributes no signal (never blocks a rebuild-only result). Wired for the one real package the ENS tree covers so far, `shankh-demo`; a real multi-package deployment would resolve a package's resolver from `pypi.shankh.eth`'s registry instead of one env var per package.

## Signals (`shankh/shankh/signals/`)
**Status: not started.** Matches the four automatic-kill signals (rebuild mismatch, ENS revocation, OSV/GHSA advisory, trusted Arkiv report) against local state. See plan-2.md "Signals".

## Kill and clean (`shankh/shankh/kill/`)
**Status: not started.** AWS quarantine/deactivate/audit sequence, file deletion, incident report. See plan-2.md "Kill and clean". Dependency spike 4 (AWS sandbox account) should land first.

## `KillSwitch` contract (`contracts/src/KillSwitch.sol`)
**Status: live on real Sepolia, one instance for `shankh-demo`.** `0x1126b7aBe8b0Db262cBa84b6b5a377D002351c5a` — takes its resolver address + DNS-encoded name at construction, and `revoke()`/`unrevoke()` actually sync the resolver's `shankh.revoked` text record. The original global instance (`0x378fDf7BbdCB33D3504e96083a7DC7Fb882a0A2C`) never did this and is superseded (ADR 0003). 6 Foundry tests passing (not yet reviewed line by line — see CLAUDE.md). A real `revoke()` call on Sepolia wrote `shankh.revoked`, confirmed read back via the real ENSIP-10 `resolve()` path — see docs/evidence.md.

## ENS tree (Sepolia, ENSv2)
**Status: live on real Sepolia.** `shankh.eth` (`0xb95110b3...`, real commit-reveal) → `pypi.shankh.eth` (`0x8634b9f5...`, emancipated with a corrected role bitmap that spike 1 had missed part of — `isEmancipated()` confirmed `true`, re-grant confirmed reverting) → `shankh-demo.pypi.shankh.eth` (`0xe2f5e5dc...` resolver, `shankh.source` scoped to the maintainer, `shankh.revoked` scoped to `KillSwitch` above). Rehearsed end to end on an Anvil fork first (`scripts/ens/register-tree-fork-rehearsal.sh`), which caught the role-bitmap bug before it hit real Sepolia; replayed for real via `scripts/ens/register-tree-sepolia.sh`. See docs/evidence.md for every address and docs/feedback/ens.md items 2–3 for what was proven and how. `ensv2-guide.md` (user-provided, from two prior ENSv2 projects) was the reference throughout. See plan-2.md "ENS name hierarchy" for the full role/handover design.

## Arkiv entities (`arkiv/`)
**Status: `shankh.report` built and proven live; `shankh.request` is schema-only.** `arkiv/src/schema.ts`, `arkiv/src/client.ts`, `arkiv/src/report.ts` — real write-then-read roundtrip against the Arkiv testnet, wired to `shankh verify` so every run auto-reports (see docs/evidence.md for the real entity/tx). Now carries `artifactSha256`/`ensRevoked` per report, so the ENS revocation signal travels with the alarm, not just the local rebuild diff. `shankh.request` has a schema but no writer yet. The `osv.mal` mirror (`arkiv/src/import-osv.ts`, supporting feature only — see docs/plan.md's Arkiv track decision) is still a stub.

## Status page (`status-page/`)
**Status: deployed, reading real live data, structured as `landing-page-playbook.md`'s pitch-deck-as-page design system.** One scrolling page in pitch order — hero, problem (a concrete before/after pair, one panel inverted), the live demo embedded mid-narrative (not linked out), how it works, then everything else collapsed into a progressive-disclosure accordion (per-track pitch, honest "what's not built yet," the full raw on-chain ledger). Three type roles never mixed: `Fraunces` serif for headlines only, Geist Sans for body, Geist Mono reserved for data/labels via the single `.label` utility. One teal accent, spent only on what Shankh adds (never the "without Shankh" side of the before/after pair). A 12-column grid with a narrow kicker column (`SectionHeader`) run down every section. One easing curve (`--ease`) reused for every reveal, the CTA's pulse, and the accordion marker; scroll-reveals stagger as a cascade via `Reveal`'s `delayMs`; a near-invisible static grain overlay. Live data (`components/sections.tsx` for the narrative, `app/page.tsx` for the fetched KillSwitch/ENS/Arkiv sections) is the same `connection()`/`instant = false` dynamic-render path as before, untouched — only its presentation and position on the page changed. `status-page/lib/killswitch.ts` reads `KillSwitch.maintainer()` on Sepolia (now pointed at the real per-package contract, not the superseded global one); `status-page/lib/ens.ts` reads the live `shankh-demo` resolver's `shankh.source`/`shankh.revoked` text records through the real ENSIP-10 `resolve()` path, reimplemented directly in viem since a Vercel function has no `cast` binary — verified against real Sepolia before wiring in (decoded the same revoked-artifact hash `cast` had); `status-page/lib/arkiv.ts` queries real `shankh.report` entities. Forced dynamic per-request (`connection()` + `export const instant = false`) so Next 16's Cache Components model can't freeze a build-time snapshot — every request is live, no hard-coded values. The ENS tree, the rebuild verifier, and the Arkiv report are no longer three separately-proven pieces — the ENS revocation signal now flows from `shankh verify` into the Arkiv report and is independently re-read live on the status page.

## CLI (`shankh/shankh/cli.py`)
**Status: `verify` is real; `demo` and `report` are stubs.** `shankh verify` runs the real rebuild diff and auto-writes to Arkiv (`--no-report` to skip). `shankh demo` / `shankh report` still raise `NotImplementedError`, wired through Typer, smoke-tested.
